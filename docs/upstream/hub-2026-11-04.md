## Monthly procedure

The first update used these steps. R-34's stand-down applies before starting future work.

1. Promote ours after current upstream is merged through integration and the whole-suite gate is green. Note the ours SHA and the upstream main SHA.
2. Build the tree from `git ls-tree -r <ours>`, filtered by the exclusion pattern, plus the Kong-cleared `README.md` and `UPSTREAM-README.md`. Use `update-index --index-info` and `write-tree`. Write the commit object with `hash-object -t commit`, with upstream main as its single parent and the bob identity. Move `_fork`'s `fork/main` with a guarded `update-ref`.
3. Prove `git diff --name-status <ours> <new>` shows only the exclusion deletions, `M README.md` and `A UPSTREAM-README.md`; `git grep -i graft` is empty; the README matches by `cmp`; and LICENSE is unchanged. Run `design/Orc-Codegraph/ledger/jobs/leak-scan.sh` on the tree and the message. Get change review, then Kong's CLEAR.
4. Publish under R-35. Re-check that there are no outside users. Back up the current remote main to private origin `refs/backup/hub/<sha>`. Push over HTTPS through gh with `git push --force-with-lease=main:<old>`. Verify compare shows ahead 1 and behind 0, and the PRs are unchanged.
5. Tag `v<version>` on the new main. Check the packed tarball's SHA-256, attach it, and publish as Latest, never with `--prerelease`. Verify `releases/latest` and the downloaded asset's SHA-256.
